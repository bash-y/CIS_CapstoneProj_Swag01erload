Scenario & Problem

SwagPc Café offers free guest Wi-Fi while running employee workstations and a Linux business server on the same flat network.

A guest-network attacker can enumerate internal hosts, exploit the café web app, and pivot to business resources — because nothing separates guests from the business.

Goal: replicate the café, demonstrate the attack on the undefended network, apply defenses, and re-run each attack to prove it is blocked, denied, or alerted.

The core problem is a flat network. Guest Wi-Fi and business systems share one broadcast domain, so a coffee-shop visitor is one hop from customer data. Our job: show the risk, then close it measurably.

Dockerized lab: pfSense modeled by Alpine+iptables router; Suricata IDS sniffs the gateway; all host ports bound to 127.0.0.1 (no LAN exposure). Entirely local and self-contained.

The whole environment is Docker containers on one host, split into two networks joined only by the firewall/router — the pfSense stand-in. Nothing is exposed to the real LAN; attack traffic stays inside the lab.

Defend Four Layers (Defense-in-Depth)

#ControlWhat it stops
1Network segmentation (pfSense/iptables): deny & log Guest→BusinessRecon & pivot across subnets
2Application hardening (input validation, bind restrictions)Web command injection
3Endpoint hardening: host firewall (authorized subnets), least-privilege, password policyDirect access to the workstation
4Monitoring: Suricata IDS + Wazuh SIEMBlindness — adds detection & alerting
No single control is enough, so we layer four. Segmentation is the big one — it severs the guest-to-business path. The rest harden what's left and make sure if someone tries, we see it.

Defend Segmentation & Endpoint

Network (US-8)

Firewall drops and logs all 192.168.10.0/24 → 192.168.20.0/24. Established/return traffic still allowed.

Endpoint (US-9)

Workstation host firewall: inbound only from the authorized Business subnet; Guest dropped & logged. Non-privileged employee account, root locked, 90-day / 12-char password policy.

Implemented as scripts in defense/firewall/ and defense/endpoint-hardening/, with the Windows Defender / secpol equivalents documented for a real Windows host.

These are my (bash-y) stories. Segmentation blocks the subnet hop. On the endpoint, even if a packet arrives, the host firewall only accepts authorized-subnet traffic, and the employee can't escalate to admin.

Challenges & Honest Limitations

  • Employee "Windows PC" is an Alpine container → endpoint controls implemented as Linux equivalents; Windows Defender / GPO steps documented for a real host.
  • Firewall is iptables standing in for pfSense — rule intent is demonstrable, not the pfSense UI.
  • A few wiring gaps found & tracked: firewall LOG rule, Suricata custom-rule mount, empty app/endpoint dirs (now being filled).
  • Docker Desktop instability slowed live runs during development.
Being upfront about simulation choices strengthens the work. We name what's modeled vs. real, and the gaps our own baseline review caught — which is exactly the kind of verification the course asks for.
